# 选题环节（每期先定刊期 → 再定头条 → 再选领域搜新闻）

## 一、刊期确认（每期第一步，必做）

**先确定这是第几期、哪天发**，否则文件名、报头日期、期号全会错。

```bash
python scripts/issue_info.py --project-dir "<项目目录>"
```

脚本按**时间锚点**推出三个数（不看目录里有没有成品）：

```
上期期号：37        （时间锚点推算（刊期台账 baseline（issues.json）））
时间锚点：38 期 = 2026.9.18    往后每过一周 +1
本期期号：38        ← 时间推算（日期定死，不看目录）
发布日期：2026.9.18（本周五）
目标文件名：38_0918.png
```

### 两条硬规则（孙哥 2026-09-15 定）

**规则一 · 时间锚点**：`assets/issues.json` 的 `baseline` 是锚点 —— **38 期 = 2026-09-18（周五）**。
发布日期落在哪一周，期号就是那一周的数；**差几周加几期**，不再靠「上期 +1」累加。

**规则二 · 时间没到，就不能 +1**：**不管目录里做没做过第 N 期**，
只有发布日期真的推进一周，期号才 +1。目录里就算躺着一个误建的 39 期（0925），
本期该 38 还是 38。

覆盖顺序：`--last-issue`（手动）> 时间锚点推算 > 扫项目目录（兜底，仅当没锚点）。
**目录扫描的结果只用来告警，不参与期号推算。**

### 告警一览

| 告警 | 含义 | 怎么办 |
|---|---|---|
| `[!] 目录里有比本期更新的成品：39期(9.25)` | 目录里躺着未来期（误建 / 提前做） | 时间没到就不算数，本期不变；确认是误建就清掉 |
| `[!] 2026.9.18 这个日期已有成品：38_0918.png` | 同一日期被**别的期号**占用 | **原样转达孙哥**，不许自己拍板 |
| `（同日期已有同名文件…）` | 同一期重出 | 正常，不用管 |

**看见 `[!]` 必须原样转达孙哥**，不要自己拍板——期号错一次，后面每期都跟着错。

然后用**一次** `AskUserQuestion` 确认（把脚本输出贴进正文）：

| # | 问题 | 形式 |
|---|---|---|
| 1 | 本期是第几期？ | 3 个选项：`<N> 期（时间推算）(推荐)` / `<N-1> 期` / `<N+1> 期`；不对就用其他写 |
| 2 | 哪天发布？ | 3 个选项：`<本周五日期>(推荐)` / `<下周五日期>` / 我指定日期 |

其他参数：
- `--date 2026-10-02`：换个发布日期，看那天发是第几期
- `--last-issue 39`：孙哥报了上期期号，手动指定（优先级最高）
- `--add 38=2026-09-18`：往台账记一条 / 换锚点
- `--no-ledger`：不用台账，退回旧的纯扫目录行为（排查用）
- `--json`：机读输出，字段含 `next_issue` / `this_issue` / `publish_date` / `name`
  / `anchor` / `future_in_dir` / `conflicts`

> **锚点通常不用每期更新**：日期推进一周，期号自动 +1。
> 只有改刊期基准（比如长假停刊后重排）才需要动 `assets/issues.json` 的 `baseline`。

## 二、公司头条（每期必问，AI 不许自编）

**第一条固定是「公司头条」**，报的是公司自己的事（新品、活动、渠道进展、经营数据、团队动态）。
这类事 **AI 搜不到，也不该编**，只能问孙哥。

**在选题（第三节）之前就把它定下来**，因为它占掉一条配额，影响后面还能收几条。

问法：一次 `AskUserQuestion`，问题「本期公司头条写什么？」

| 选项 | 说明 |
|---|---|
| 我口述要点 | 孙哥把要点写给我，我整理成 ≤250 字、小标题格式 `公司头条｜<正标题>`，回给他确认 |
| 先给我几个方向挑 | 我按常青的四类各列一个方向（新品/上新、大促备战、渠道与线下门店、经营数据与团队），他挑一个再补细节 |
| 本期不设头条 | 本期直接从行业新闻排起，第一条用领域主题词（此时第一条**不是**头条） |

拿到要点后：
1. 压到 **≤250 字**，跑 `count_chars.py` 核一遍。
2. **头条配图优先用孙哥给的公司实拍/设计图**，不要一上来就 AI 生成（AI 画不出公司的产品和门店）。
   他给不了图再走 AI 生成，并先告知额度消耗。
3. 头条定稿后再进第三节，别和后面的行业新闻一起铺。

> 无人值守（定时任务）时**没人可问**：跳过头条，从行业新闻排起，
> 交付时明确写一句「本期头条位留空，需要补请告诉我」。

## 三、为什么要选题

旧版把内容框死了：`content-guide.md` 写死 5 条检索线，每期都跑同一批关键词，
结果期期都是「电商大促 / 平台动向 / 跨境电商」这三件套，读者看久了会腻。

现在改成：**先问孙哥这期想覆盖哪几个领域，再按选定的领域去搜**。
领域池有 14 个（`assets/topics.json`），每期从中动态挑候选，轮换着来。

> 三个概念别混：
> - **刊期**（第一节）= 第几期、哪天发。每期必确认。
> - **头条**（第二节）= 公司自己的事，固定摆第一条，每期必问，**不参与领域轮换**。
> - **领域**（这里）= 头条之外报什么方向。从 14 个里轮换，最多 4 个（头条 + 4 = 5 条上限）。
> - **品类与业务范围**（`content-guide.md` 二、三节）= 哪些内容能写进去。这个**不变**：
>   国内电商 / 本地线下母婴集合店 / 欧美跨境亚马逊三条业务线，
>   品类只写婴童纺织用品与童装。领域换了不等于品类放开了。

## 四、领域池

文件：`assets/topics.json`。14 个领域，每个含主题词、说明、检索关键词、常用来源、适用月份、基础权重。

| 领域 | 说明 | 当季 |
|---|---|---|
| 电商大促 | 各平台大促档期、招商节奏、玩法与补贴力度 | 9/10/11 |
| 平台动向 | 五大主力平台的规则、工具与流量玩法变化 | 全年 |
| 跨境电商 | 亚马逊欧美站档期费用与儿童睡袋合规 | 8–12 |
| 合规与标准 | 儿童用品安全标准、质检抽检与平台准入 | 全年 |
| 行业趋势 | 童装母婴市场规模、赛道结构与功能面料 | 全年 |
| 供应链与产业带 | 织里等童装产业带、面料与棉价、产能订单 | 3/4/8/9/10 |
| 营销风向 | 直播、达播店播与内容种草的新玩法 | 全年 |
| 消费洞察 | 母婴人群画像与新生代父母消费观 | 全年 |
| 品类机会 | 具体品类的增长信号（防晒/家居服/睡袋等） | 全年 |
| 竞品动态 | 童装品牌的新品、开店、财报与联名 | 全年 |
| 政策与宏观 | 育儿补贴、生育支持与促消费政策 | 全年 |
| 渠道与私域 | 线下母婴集合店、门店经营、会员与即时零售 | 全年 |
| 物流与履约 | 快递旺季价格时效与仓配成本 | 9–12/1 |
| AI 与新工具 | AI 在电商运营、设计与客服中的应用 | 全年 |

**要加领域**：往 `pool` 里追加一项，`name` 起一个新主题词，跑一下
`python scripts/topic_menu.py --list-all` 确认能读出来即可。

**主题词的坑**：`name` 必须与 `content.json` 里 `sections[].topic` 用同一套词，
轮换统计是按这个词匹配的。历史用过的旧词（`报告解读`/`趋势洞察`/`规则风向`）
已登记在各领域的 `aliases` 里，所以统计能认出来。
`公司头条` **不在池子里** —— 它每期都有、不轮换，脚本会自动忽略它。

## 五、选题流程

### 第 1 步 · 生成候选

```bash
python scripts/topic_menu.py --project-dir "<项目目录>" --date <刊期日期>
```

脚本会扫项目目录里的历史 `*_content.json`，算出每个领域最近一次被用的期号，
然后输出：历史覆盖 → 上期已用告警 → 本期推荐 4 个（避开上期）。

加 `--json` 可拿结构化结果（拼 AskUserQuestion 用）；
加 `--list-all` 看完整 14 个领域。

### 第 2 步 · 问孙哥

用**一次** `AskUserQuestion`，三个问题：

| # | 问题 | 形式 |
|---|---|---|
| 1 | 本期覆盖哪些领域？ | `multiSelect: true`，4 个候选（label = 领域名，description = 该领域一句话说明） |
| 2 | 头条之外再收几条？ | 3 条（默认）/ 2 条 / 4 条（头条 + 4 = 满 5 条上限） |
| 3 | 有没有特别想跟的方向？ | 4 个动态选项，如「跟一次跨境合规专题」「盯某个平台的新规则」「没有，按你推荐的来」 |

同时在**正文里**把领域池完整 14 个列出来（脚本 `--list-all` 的输出直接贴），
并说明「池子里没有想要的方向，用其他直接写」。

第 1 问给 4 个候选是因为 AskUserQuestion 上限就是 4 个；
候选之外的选择靠正文里的完整清单 + 自由输入兜住。

### 第 3 步 · 定向检索

按选定领域的 `keywords` 跑 `WebSearch`（`freshness: d10` 左右）。
每个领域 2–3 条查询，**只跑选中的领域**，不要顺手把没选的也搜了。
关键词要冠上 `母婴` / `童装` / `婴童` / `母婴店` 之类的品类限定词（见 `content-guide.md` 第二节）。

### 第 4 步 · 回到原流程

列新闻清单（含来源与关键数字）→ `AskUserQuestion` 问收录哪几条 / 配图方式
（期号、日期、条数前三步已定）→ 写 content.json（**头条放第一条**）→ 核字数 →
配图 → build.py → present_files。

## 六、无人值守时怎么办

每周五 09:00 的定时任务没人可问，规则：

1. **刊期自己算**：跑 `issue_info.py` 取本期期号与本周五日期，**不再询问**。
   现在按时间锚点推算，不会算错号，可以放心跑；若报「目录里有比本期更新的成品」，
   **照常出图**，交付时提一句「目录里有个 N 期成品比本期新，疑似误建，要不要清掉」。
2. **头条跳过**：无人可提供，头条位留空，交付时说明「需要补头条请告诉我」。
3. **领域按推荐走**：`topic_menu.py` 推荐什么就搜什么，**不要退回旧的三件套**。
4. **交付时说明**：本期选了哪几个领域、各自为什么入选（哪个是当季、哪个是久未覆盖），
   让孙哥一眼能判断要不要换。
5. **给一句回退口**：「想换领域/补头条，回我一句，我重搜重做」。
6. 脚本推荐不足 4 个（领域池太小或历史异常）时，按池里权重顺位补齐。

## 七、轮换规则

- 同一领域**不连续两期**出现。特殊情况（大促爆发期）可以连，但至少隔一期。
- 每期**至少 1 个领域**是最近 2 期没出现过的。
- 「电商大促」在 9–11 月是主线，可以高频出现，但不必每期都占第一条。
- `公司头条` 不参与轮换，永远第一条。
- 脚本的 `-80` 分惩罚只是**启发式建议**，不是硬规则 —— 孙哥指定了哪个领域就用哪个。

## 八、评分逻辑（想改就看这里）

`scripts/topic_menu.py` 里的候选排序：

```
score = weight                                    # 基础权重，常青主线为正
      + 60  （从未被用过）  或  min(50, 间隔期数 × 15)   # 越久没写越优先
      + 25  （当季：当期月份落在 months 里）
      - 80  （上期刚用过）
```

按分数降序取前 N（默认 4）。上期用过的领域被挤出推荐，但会单独列在
「上期已用」里，孙哥想继续写随时可以点。

调参就在脚本顶部的 `STREAK_PENALTY` / `FRESH_BONUS` / `SEASON_BONUS` / `GAP_STEP` / `GAP_CAP` 五个常量。
