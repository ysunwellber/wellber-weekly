# 内容口径（孙哥定的规则）

排版和内容解耦：排版只认 `content.json`，所以**文案可以人工审核后随便改**，改完重跑一次即可，版式不会跑偏。

> 本文件的**第一节（硬约束）**与**第二节（业务与品类范围）**是孙哥 2026-09-15 明确的"设死"框架，
> 不留裁量空间。第三～六节是可变的写法与选题方法。

## 一、硬约束（框架，不许自由发挥）

| 规则 | 值 | 怎么核 |
|---|---|---|
| 每条正文字数 | **≤250 字**（含标点、不含空格） | `python scripts/count_chars.py <文件> --limit 250` |
| 板块总数 | **最多 5 条**（含头条），默认 3–4 条 | — |
| **第一条** | **固定为「公司头条」**，**每期都必须问孙哥**，AI 不许自编 | 见第七节流程第 2 步 |
| 先头条、后其余 | 头条内容**定稿之后**再去找后续板块，不要一起铺 | 见第七节流程 |
| 每条段落数 | 1 段（可选 2 段，不要 3 段以上） | — |
| 段落 vs 配图 | 每块 1 张配图 | — |
| 主题词 | 头条固定写 `公司头条`；其余取自当期选定领域（`assets/topics.json`） | 见 `topic-menu.md` |

- **250 字**是 2026-09-15 定的：原稿 901 字，孙哥要求压到「每条不超过 250 字」。压缩时**优先保留硬数字**
  （如 111.5 点、820 元券、293%、3200 亿），砍掉修饰性表述和重复的背景交代。
- **5 条上限**是 2026-09-15 定的：板块多了长图过长、微信里读不完。头条占一条，所以头条之外最多 4 条。
- **头条为什么必须问**：头条报的是公司自己的事（新品、活动、渠道进展、经营数据、团队动态），
  **AI 搜不到、也不该编**。只能问孙哥，他给了才写；他说这期没有，就直接从行业新闻排起（此时第一条不是头条）。

## 二、业务与品类范围（搜新闻的边界，很重要）

公司业务是**三条线**，新闻必须与其中至少一条相关，否则不写：

| 业务线 | 说明 | 对应内容方向 |
|---|---|---|
| **国内电商** | 抖音 / 天猫 / 拼多多（主力），京东 / 唯品会（次要） | 平台规则、大促节奏、流量玩法、类目机会 |
| **本地线下母婴集合店** | 线下门店零售、会员运营、即时零售/闪购 | 母婴店客流与经营、连锁扩张、门店数字化、私域复购 |
| **欧美跨境** | **亚马逊**（美国站 / 欧洲站），主推**儿童睡袋** | 亚马逊档期与费用、欧美儿童睡眠用品合规与召回 |

**品类**：**婴童纺织用品 + 童装**（婴儿睡袋、婴儿内衣、儿童家居服、童装、亲子装、校服等纺织类目）。

**不相关品类，直接删**：
- 家电数码国补、3C 换新补贴 → 品类不相关
- 成人服饰大盘、汽车、房产、食品饮料 → 不写
- 美妆个护、宠物 → 不写（除非与母婴纺织强相关）

> 早期这里只写了「儿童用品 / 童装 + 跨境」，**漏了线下母婴集合店这条业务线**，
> 2026-09-15 补上。现在搜新闻时，线下母婴零售的题材也算正相关。

## 三、平台白名单

**主营**：抖音、天猫、拼多多。**次要**：京东、唯品会。
**跨境**：亚马逊（美国站 / 欧洲站）。**线下**：不涉及平台，涉及门店/连锁/即时零售平台即可。

**不写的平台**：速卖通、快手、Temu、Shopee 等（与公司渠道无关）。
> 注：**只要涉及平台就按白名单**。若本期选的是不绑平台的领域（如行业趋势、政策与宏观、
> 供应链与产业带），白名单自然用不上，不必硬凑。

## 四、每条只讲一个立意

不要堆砌信息。定稿后应该能用一句话说出这条在讲什么，说不出来就是信息堆砌，要重写。

- **头条**的立意 = 公司这周最值得全体知道的那件事，一条讲清（新品/活动/渠道/数据/组织择一）。
- **其余各条**的立意跟着当期选定的领域走，**不预设**。

举例（第 38 期的两条，仅作风格参考，**不是固定模板**）：

- 立意 = **「消费节奏已经拉起来了」**：物流指数先动 → 各平台把中秋档铺满 → 双11 预热接上，节点首尾相接。
- 立意 = **「备货与合规要同时交卷」**：Q4 档期与费用 + 睡袋安全标准收紧。

> 早期这里写死了「第一条讲消费节奏、第三条讲备货合规」，结果每期都长一个样。
> 现在立意由当期选题决定，见 `topic-menu.md`。

## 五、文风

- **密集、带数字、陈述句**，不写评论口吻
- 段末可以引一句判断，用「业内认为…」「业内观察认为…」
- 小标题格式 `主题词｜正标题`
- 主题词：**头条写 `公司头条`**；其余取自当期选定的领域，完整可选清单在 `assets/topics.json`（14 个），
  怎么选用见 `topic-menu.md`
- 往期用过的主题词：`报告解读` / `电商大促` / `平台动向` / `趋势洞察` / `营销风向` / `规则风向` / `跨境电商`
  （其中 `报告解读`、`趋势洞察` 已归入「行业趋势」，`规则风向` 已归入「平台动向」）

## 六、检索方向：由当期选题决定

**不再有固定的几条线。** 每期先走选题环节（见 `topic-menu.md`）定下要覆盖哪几个领域，
然后**只按选定领域**去搜。**头条那一条不检索**（公司自己的事，搜不到）。

`assets/topics.json` 里每个领域都给了 4–6 个检索关键词和常用来源，直接拿来跑 `WebSearch`
（`freshness: d10` 左右）。每个领域 2–3 条查询即可。

**检索时必须带业务口径**：关键词冠上 `母婴` / `童装` / `婴童` / `母婴店` 之类的限定词，
否则会搜出一堆与公司无关的大盘新闻。跨领域常备来源：中服协、织里童装城、中童传媒、
网经社、电商日报、亿邦动力、亚马逊卖家平台公告。

> 旧版在这里列了「①平台大促节奏 ②抖音电商玩法 ③跨境电商 ④行业趋势 ⑤平台合规」这 5 条固定线，
> 每期照跑，是内容框死的根源，2026-09-15 撤掉。

## 七、流程要求

顺序是**定死的**，不要跳步、不要并步：

1. **刊期确认**：跑 `scripts/issue_info.py` → `AskUserQuestion` 确认**本期期号与发布日期**
   （默认本周五发布）。见 `topic-menu.md` 第一节。
2. **公司头条（必问）**：问孙哥这期头条写什么。他给了要点就整理成 ≤250 字的稿子给他确认；
   说没有就跳过头条，从行业新闻排起。**AI 不许自编头条。**
3. **选题**：跑 `scripts/topic_menu.py` 生成候选 → 一次 `AskUserQuestion` 问清
   本期覆盖哪些领域 / **头条之外再收几条** / 有没有特别想跟的方向。详见 `topic-menu.md`。
4. **定向检索**：只按选定领域的 `keywords` 搜，整理成候选新闻清单（含来源与关键数字）。
5. **列清单确认**：把清单给孙哥过目 → 确认收录哪几条 / 配图方式。不能跳过。
6. 配图用 AI 生成前要**先告知额度消耗**。
7. 定稿后直接落地，不要反复讨论。
