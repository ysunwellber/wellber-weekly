# 事实核查（出稿之后、交付之前）

孙哥 2026-09-25 提的：**每次出新闻之后，再用更多信源核实一遍内容可靠性，尤其是数据和趋势类的，
确保完全可靠再推；AI 判断不了的，输出「判断指令」给作者。**

此前技能里**只有天气**做了多源验证（v1.5.0，同一份数据 7 源取中位数）；
新闻正文一直是「搜到什么写什么」，**没有任何核实环节** —— 这是 v1.5.3 补的。

> 两者不是一回事，别混：
> - **天气**：同一份客观数据，多个源取**中位数/众数**（数值融合）。
> - **新闻核查**：同一句**断言**，去找**第二个独立来源**证实或证伪（判断题）。

---

## 一、什么时候做

挂在流程里，**写定 `content.json` 之后、生成配图之前**（这样核查导致的改稿不用重出图）。

```
… → 写 content.json → 【事实核查】 → 生成配图 → build.py → 交付
                          ↑ 这里
```

- 复查对象是 **`content.json` 的正文**，不是成品图。
- `build.py` 跑完会顺带**提醒**「本期有没有做核查、有没有高危未处置」（只提醒，不拦）。
- **交付前必须过卡口**：`--report` 返回 0 才推。

---

## 二、什么算「可核查断言」

`fact_check.py` 会机械扫每句话，命中下面任一类就抽出来（纯修辞不抽）：

| 类别 | 例 |
|---|---|
| 数字 + 单位 | `1340.6 亿件`、`8735 元/吨`、`均价 91 元` |
| 百分比 / 幅度 | `同比增长 7.4%`、`跌幅约 7%` |
| 趋势 | 增长 / 下滑 / 回暖 / 承压 / 上调 / 高于… |
| 绝对化 | 首个 / 唯一 / 最大 / 创历史新高 / 超 100 亿 |
| 时间 | `9 月 8 日`、`2026 上半年`、`Q4` |
| 期限 / 生效日 | 截至 / 截止 / 生效 / 实施 / 落地 |
| 事实性事件 | 召回 / 抽检 / 处罚 / 新规 / 涨价 / 招商 / 发布 |
| 引用 / 预测 | 「数据显示」「业内认为」「预计」「有望」 |
| 标准 / 法规编号 | `16 CFR 1250`、`EN 16781`、`GB 31701` |

每句话最多抽一条，同句重复不重复计。

---

## 三、风险分级（机械规则，不用人判断）

| 级别 | 触发条件（任一） | 含义 |
|---|---|---|
| **高** | 数据 + 趋势词；数据 + 绝对化；带百分比/幅度；金额/规模/份额类数据；标准/法规编号；期限/生效日；**公司头条里的数字** | 写错会**误导经营判断**，必须处置 |
| **中** | 有数字 / 趋势 / 引用 / 时间 / 事件 / 标准但未达高危 | 常规复核，建议看一眼 |
| **低** | 纯定性表述 | 可放过 |

**公司头条里的数字一律高危** —— 那是公司内部经营数据，外部**永远查不到**，只能作者确认。

---

## 四、怎么核（核查动作）

对每条断言，按下面的顺序走，尽量用 `suggested_queries` 里给出的查询：

1. **先找一手**：官方公告、政策原文、标准文本、平台规则中心、统计公报、财报。
   → 找到即 A 级，基本可以定案。
2. **再补一个独立来源**：换机构、换媒体，**注意别拿同一篇的转载充数**。
   多家转载同一篇稿子 **≠ 多源**；要回溯到**首发**是谁。
3. **核时效口径**：数据带统计期吗？（哪年哪月、哪份报告、截止到哪天）
   「最新数据显示」而没有日期 = **不通过**。
4. **核口径陷阱**：同比还是环比？销售额还是销量还是 GMV？含税吗？线上还是全渠道？
   **高增长一定要看基数** —— 小基数翻倍不算趋势。
5. **核生效日**：标准/新规要确认 **是否已生效**，别把「即将生效」写成「已实施」。

> 换关键词的技巧：把结论词换成中性词（`暴涨` → `数据`），加上 `官方`、`原文`、`统计期`、
> `辟谣`、`澄清`、`更正`，往往能翻到原始出处或反面证据。

## 五、结论四档

把结果写回 `factcheck_<name>.json` 的 `status`：

| status | 含义 | 什么时候用 |
|---|---|---|
| `confirmed` | 已确证 | ≥2 个独立来源，且至少 1 个 A/B 级；或 1 个 A 级（官方原文） |
| `softened` | 已弱化 | 查不实但**值得保留**：去掉具体数字、改成「明显增多」这类表述，删掉绝对化词 |
| `dropped` | 已删除 | 查不实、也无保留价值（尤其是会被当成事实引用的硬数字） |
| `unjudgeable` | 无法判断 | AI 判不了 → **必须写 `action`（判断指令）给作者** |

同时填 `verdict`（一句话结论）和 `note`（核查过程：查了什么、各家怎么说）。
`sources` 里要留下**实际查到的来源**（`{tier, title, url}`）。

弱化方向见 `assets/sources.json` → `rules.softenWords`：
`据…数据显示` → 去掉数字；`增长 300%` → `增速较高`；`首个/唯一` → `较早/头部之一`；
`将于 10 月上线` → `按其排期预计 10 月上旬（官网未必已公布）`。

## 六、「判断指令」怎么写（给作者）

凡 `unjudgeable` 的，`action` 里写一句**作者一句话就能答**的话。句式：

> **【要你定夺】** + 一句为什么 AI 判断不了 + 2~3 个可选处置

典型场景与写法：

| 场景 | 判断指令 |
|---|---|
| 公司经营数据（头条） | 「头条里的数字外部无法核实。请确认：① 口径（同比/环比/累计）② 是否可对外披露 ③ 保留具体数字吗」 |
| 只有单一自媒体来源 | 「只有一篇自媒体转述，找不到官方或第二来源。请定夺：① 删掉这个数字 ② 改成「明显增多」 ③ 你认可，保留原文（若选 ③ 请告知来源）」 |
| 公开来源与文稿**对不上**（最常见） | 「公开报道说是 X 月发布，文中写 Y 月实施；发布日与生效日可能是两个日子，但查不到官方生效日。请定夺：① 改成「X 月上旬发布、Y 月初生效」② 只写「近期」③ 你确认原文正确」 |
| 预测类没有预测方 | 「找不到是谁预测的。请定夺：① 改成「业内传闻」② 删掉 ③ 你补上预测方与报告名」 |
| 口径歧义 | 「『增长』没写是同比还是环比，基数也不明。请确认口径，或改成「较上期提升」」 |

报告里这部分会单独成区（黄色卡片），**一眼就能看到要你答什么**。

## 七、交付前卡口

`--report` 的退出码就是卡口（阈值在 `assets/sources.json` → `rules.gate`）：

| 情况 | 退出码 | 动作 |
|---|---|---|
| 高危断言仍有 `pending` 或 `unjudgeable` | **2** | **不许推**，先把高危处置掉 |
| 中危断言仍有 `pending` | 0（仅提醒） | 建议看一眼 |
| 高危全部落到 confirmed / softened / dropped | **0** | 可以交付 |

命令：

```bash
# 1) 抽取
python scripts/fact_check.py --content 39_content.json
# 2) 逐条核查、回填 JSON
# 3) 出报告 + 过卡口（0 才可以推）
python scripts/fact_check.py --content 39_content.json --report
```

产物（默认落在 content.json 同目录）：

| 文件 | 用途 |
|---|---|
| `factcheck_<name>.json` | 待核清单 / 回填载体（**唯一需要手改的文件**） |
| `核查清单_<name>.md` | 人读版，带每条建议查询 |
| `事实核查报告_<name>.html` | 逐条明细 + 给作者的判断指令（手机可直接看，无外链资源） |

## 八、无人值守（定时任务）怎么办

每周五 09:00 没人可问，规则：

1. **照样跑核查**（不跳步）。
2. 高危 `pending` → **自己处置**：能核实的核实（`confirmed`）；
   核不实的按 `softenWords` **弱化**（`softened`）或**删掉**（`dropped`）；**不许把未核的数字留在稿子里**。
3. **不产生 `unjudgeable`**（没人答），改为 `softened` + 在 `note` 里写明「无人值守，已弱化，请孙哥复核」。
4. 交付时**列一份清单**：「本期核实了 N 条，其中 M 条因核实不实已弱化/删除：…」
   让孙哥一眼知道改了哪儿，并留一句回退口（「不同意就说一声，我改回来」）。

## 九、踩过的坑

- **「多家转载」不是多源**：同一篇稿被 5 个站转，仍是 1 个来源。必须回溯首发。
- **发布日 ≠ 生效日**：2026-09-25 核第 39 期时踩到 —— 文中写「9 月 8 日实施的《商家体验分规范》」，
  公开报道（网经社 8/7、腾讯新闻 8/7）都说该规范是 **8 月上旬发布的新版**。
  两者可能是发布/生效两个日子，但公开渠道查不到官方生效日 → 这一条只能交给作者定夺。
  **凡是「X 月 X 日实施/生效」都要多问一句：这是发布日还是生效日。**
- **原文里的限定条件最容易被吃掉**：同一条里官方写「一次性扣 10 分，**近 30 天累计不超过 10 分**」，
  文稿省略后半句，严重程度就被说高了。核的时候要**回到原文全句**，不只看那个数字。
- **政策/标准名称要对齐**：官方全名《2026年抖音电商商品卡免佣扶持政策》，文稿写成《商品卡返佣扶持政策》，
  数字都对，名字不对 —— 引用型新闻要核**正式名称**。
- **口径比数字更容易错**：销售额 / 销量 / GMV / 订单量；同比 / 环比；
  线上 / 全渠道。数字对、口径错，结论就反了。
- **统计期必须落到字面**：「2026 上半年」「1—8 月」这种要跟来源对得上；
  「最新」「近期」这种没有口径时间的，一律不通过。
- **报告里别写 markdown 星号**：`fact_check.py` 的 `rich()` 会把 `**粗体**` 转成 `<b>`，
  但其他字段别塞 HTML。
